## Prompt

An alert shows an unusual AWS IAM access key usage from a new geography. Describe investigation and containment steps for a cloud-focused SOC team.

## Response

Certainly! Here's a structured approach for a cloud-focused SOC team investigating and containing unusual AWS IAM access key usage from a new geographic location:

**Investigation Steps**

**Validate the Alert**

- Confirm if the alert is generated by a reliable security tool (e.g., AWS CloudTrail, GuardDuty, SIEM).
- Check if the geographic anomaly matches the organization's normal access patterns or known remote users/travelers.

**Identify the Access Key and Associated User**

- Extract the IAM access key ID from the alert.
- Use AWS IAM and CloudTrail logs to identify the IAM user or role that owns this access key.
- Determine whether the key belongs to a human user, an application, or a service.

**Examine Recent Activity**

- Analyze AWS CloudTrail logs to review all actions taken using that access key in previous days/hours.
- Look for suspicious activities such as privilege escalation attempts, creation/deletion of IAM users or policies, unusual data accesses (S3 buckets), or launching of compute instances.

**Verify User or Service Context**

- Check if the user reported recent travel or remote work from the new geography.
- Confirm with HR or the user's manager whether access from this location is expected.
- Check for known legitimate automation jobs or CI/CD pipelines that might explain usage.

**Assess Impact and Scope**

- Identify AWS resources accessed or modified using this key.
- Determine whether credentials or sensitive data might have been compromised or exfiltrated.

**Look for Lateral Movement or Persistence**

- Investigate if new IAM policies or keys have been created.
- Review CloudTrail and AWS Config for changes in permissions or suspicious roles.
- Check for creation of backdoor accounts or unnoticed changes.

**Containment Steps**

**Immediately Disable or Rotate the Compromised Access Key**

- Disable the IAM access key temporarily to stop ongoing unauthorized use.
- Alternatively, if usage is confirmed malicious, delete the access key.
- Notify the key owner/user to rotate credentials securely.

**Force Re-authentication and Credential Rotation**

- Require password changes, re-issue new keys, or re-configure service tokens as appropriate.
- For services using these keys (automation, apps), update credentials securely.

**Review and Harden IAM Policies**

- Ensure least privilege principles are in place.
- Remove overly permissive permissions or unused IAM entities.

**Implement Conditional Access Controls**

- Enforce multi-factor authentication (MFA) for all privileged users.
- Use AWS IAM Conditions to restrict access by geographic location, IP address, or device.

**Monitor for Repeated or New Anomalies**

- Increase logging granularity (enable AWS CloudTrail insights).
- Set up alerts on any new unusual access key usage or privilege escalations.

**Coordinate with Incident Response/Forensics Team**

- Preserve logs for forensic analysis.
- Conduct a root cause analysis to identify how the key was compromised (phishing, leaked in code, insider threat, etc.).

**Communicate with Stakeholders**

- Inform affected business units and leadership about the incident and response actions.
- Engage AWS Support if necessary for impact assessment or recovery.

**Summary Table**

| Step | Action |
|---|---|
| Investigate | Validate alert, identify key and user, review activity logs, confirm legitimacy |
| Scope | Assess impact, check for lateral movement or persistence |
| Contain | Disable/rotate keys, enforce MFA, tighten IAM policies, restrict access by geo/IP |
| Monitor & Prevent | Enhance monitoring, alerting, and conditional access |
| Follow-up | Conduct root cause analysis, preserve evidence, update incident report |
